# W22 认证本机转发：离线合成阶段

## 交付范围

承接W21，在tests中实现127.0.0.1 TCP单实例一次能力绑定及独立stdio转发进程；无新依赖、不改生产启动器/数据库/UI。只有本项目MCP桥持合成task读凭据，relay只获得短时本机能力。错误、过期、重复绑定和跨端点旧能力拒绝；不重连、不重放、不自动恢复旧进程。单在途、写回调背压、双向累计额度及请求/写出截止期控制资源。

工作位置D盘主工作区。原客户端启动0、模型调用0、用户凭据复用0、窗口操作0、系统隔离变更0。HANDOFF未更新，管家未构建。W20真实FAILED及250项AT/CA NOT_RUN不变。

## 实际合成操作路径

1. 新临时库和合成task/grant，启动本项目MCP桥及本机端点。
2. 独立relay子进程以一次能力认证；通过stdio initialize/initialized、task_get，真实CoreService返回相同task ID及draft。
3. 1000次状态快照不新增业务写入或模型回合。
4. 正常停止顺序：拒绝新帧→已接收HTTP请求完成/响应写出→桥stdin EOF→真实桥close及最终证据→relay关闭控制帧→relay实际exit0→所属Node宿主EOF/exit0。重复stop不会重复关闭宿主。
5. 撤权仍由每次CoreService访问拒绝；认证连接不延长业务grant。

这是后端合成用户路径，非原生窗口点击、真实Codex任务或产品验收。独立Node宿主不是原客户端；崩溃fixture只用于错误注入。编译走查仅MCP桥使用dist，其余装配仍为tests代码。

## 反例及根因修复

29项专项：握手/绑定、过期/静默/重复能力、跨重启拒绝、原JSON-RPC id/error、重放拒绝、UTF8/JSON/截断/帧与累计上限、慢写/写失败、真实relay崩溃、端点子进程崩溃、请求超时、撤权、未知relay退出、在途排空与停止后拒绝。

- 初始未实现红灯暴露fixture清理注册晚于可能抛错的构造；提前注册后初始化失败也能清理。原运行只终止已核实的本次测试runner，所属桥随后退出，未碰原客户端。
- 首次实现8/9：撤权测试忘记initialized通知，返回的是协议错误，补正确握手，不放宽生产会话要求。
- 新反例发现超时写监听器残留、输出累计上限缺失；补明确超时销毁/监听清理及每输出流1MiB累计限制。
- relay强杀在Windows体现为连接重置，补精确错误码归类而非笼统失败；未吞错或改成功。
- closed早于stdout错误回调时，先前catch可能把真实写失败当正常输入中断。定向反例稳定红灯后，仅允许预期输入流销毁错误，写失败继续向外拒绝；仍需relay实际退出证明。
- 未知relay退出的详细错误被W21监督器归一化；加强错误码断言后，修复relay自身回调边界保留首次原因，保持W21原实现不动。
