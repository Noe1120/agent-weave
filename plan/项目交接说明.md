## 1. 先理解要做什么

用户希望构建类似微信的项目群：人类创建群、邀请不同原生 Agent，按项目需要分配职责；成员共享有权读取的项目事实、协作数据和成果，可以互相求助，共同交付一个项目。

目标成员包括 Codex、Claude Desktop、DeepSeek Harness。规划/前端/后端由哪个成员承担，始终由用户决定，不预设厂商能力排名。必须保留原客户端身份：不能用 Claude Code 或 API 调用替代 Claude Desktop 后，声称已完成指定客户端接入。

内置可更名管家使用用户提供的生成模型 API，采用 LangGraph、受限 ReAct 和授权 RAG 处理计划、解释与协作建议；确定性群服务掌握真实权限、任务、预算和执行状态。管家不是拥有全部权限的超级成员，也不替换工作 Agent。

### 1.1 不得在实现中悄悄改变的要求

1. 单独 @ 一个 Agent 的指令、回复及派生资料仅在相应受众内可见。相同成员的公开与私密执行必须隔离，不仅仅在聊天 UI 隐藏。
2. 进度查询读既有状态投影，不发 prompt/steer/cancel/restart，不触发额外模型回合，不打断工作。
3. 普通新指令与回答活动等待请求分开。continuation_reply 必须绑定有效请求、run、epoch 和回答者权限，不能冒充审批。
4. 同项目同逻辑文件跨所有 worktree 同时仅一个有效写入者；worktree 不是安全沙箱。
5. 失联或租约过期不能证明停止。旧写入能力无法确认撤销时保持隔离，不能换目录重试同一路径。
6. 写入由 Broker 受控完成，并关联实际 diff、journal、变更 Markdown 与本地 Git 检查点；代码存在不等于已验收，不默认 push/merge。
7. 平台数据库是业务权威；图、聊天、模型总结、已读回执不能代替实际状态、同步或验收证据。
8. 消费上游成果使用一致项目快照和完整 changeset；WIP 依赖要显式记录，上游失效阻断受影响写入与合并。
9. 人工修改同样遵守停止/撤写、检查点、独占范围、真实 diff、同步和重验流程。
10. 读取、联网、发送和发布分别授权。私密载荷披露与计划执行批准分开；获准给成员看，不等于获准发给另一模型服务方。
11. 子任务、求助、重试累计到同一根工作流预算；未知费用不当零，失败任务不靠换 root 消除历史。
12. 验收基线独立于作者候选测试；删除断言、修改验收或模型一致同意，均不能直接把失败改成通过。
13. 计划应用、管家流程结束、全部工作成果交付是三个概念；暂停派工、停止计划和撤销代码也是不同操作。

详细规则分别以02、07–12为准。本清单只帮助接手者避免走错方向，不另建一套规范。
