## 为什么现在需要决定

本轮仅用 Windows API/命令元数据核实：Windows 10.0.22631、C: NTFS、当前进程非提升、本地账户管理命令可用。没有列出账户秘密、读取聊天、创建账户、改 ACL/防火墙、安装系统组件或启动原客户端。未确认已有可用的独立测试机或虚拟机。

## 推荐环境

优先使用可回滚的独立 Windows 测试机/虚拟机，在其内部实施既定 Win-SID-Broker-1，不把“运行在 VM”本身当隔离通过，也不将 VM 静默变更为替代部署方案。先只使用仓库自有 fixture、合成秘密与合成 Git 项目，不接入真实凭据或付费模型。

实际环境由用户指定；不擅自启用 Hyper-V、购买云主机、下载 Windows 镜像或克隆用户系统/profile。若用户选择本机测试，必须明确批准创建专用身份、测试根目录 ACL 和限定网络策略；不能据普通开发授权执行。

## 首轮系统变更提案

授权后先生成具体清单并核对碰撞，不复用已有同名账户或目录。拟在选定环境创建 `AWG0Service`、`AWG0Broker`、`AWG0Worker01` 三个非管理员本地测试身份，测试根默认 `C:\AgentWeave-Isolation-Test`（必须事先确认不存在或专属本次测试）。凭据不得写入仓库/命令行/日志。

1. 在专属根内创建 service、broker、worker、readonly-snapshot、denied-canary 子目录；按 09 §4 显式配置 ACL，只修改这些目录及本次自有身份。
2. worker 只读公开快照、只写自己的候选/cache/temp，不能读写 service DB/token、broker 权威仓库或另一 worker 的合成 canary。
3. 在专属测试环境为 fixture 使用最小 IPC/网络 allowlist，默认无外网。具体防火墙/服务规则名带 `AgentWeave-G0-` 前缀，变更前导出本次涉及的规则状态，不重置系统规则。
4. 实测 open/read/write/rename/delete、hard link/reparse、子进程、继承句柄、撤权后旧句柄、退出与失联；保存成功与拒绝证据。
5. 未通过不得将 fixture/Job 结果升级为真实原客户端隔离；DSH/Codex/Claude 需随后按固定发行版、CC Switch 路由及独立明确授权同配置复验。第一轮不自动复用任何用户凭据、不触发模型。

## 回滚和停止

- 先停止并核对本次自有进程；未知句柄/未知进程不删目录、不释放隔离。
- 仅撤销清单中本次创建的规则与身份，恢复本次保存的 ACL；不删除/改名原用户、原应用配置或用户历史。
- 遇到已有名称、非专属路径、权限不符、跨边界句柄或无法还原的系统变更立即停止，记录原因。
- 虚拟机快照是回滚辅助，不替代测试日志或源仓库提交。
